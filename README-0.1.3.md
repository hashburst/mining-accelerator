# HashBurst Mining Accelerator 0.1.3

0.1.3 separates volatile BTC/EUR market telemetry from mining policy. It does not implement production apply.

## Safety and compatibility
- `history.sqlite` schema is unchanged from 0.1.2.
- Existing local identity salt is never regenerated by read-only commands.
- `policy.json` no longer accepts `btc_fiat` or `price_observed_at`.
- `market-observation-v1` is a separate short-lived artifact with two distinct sources, response hashes, freshness and deviation checks.
- `status` and `recommend` require `--market` and fail closed if the artifact is invalid.
- No URL is stored in the market artifact; source URLs are supplied through process environment variables.
- `apply_supported` remains false. Real apply belongs to the authenticated Node Stage B executor.

## Migrate a 0.1.2 policy without overwriting it
`python accelerator.py migrate-policy --source OLD_POLICY --out NEW_POLICY --report REPORT`

## Collect a dual-source market observation
Set `HB_MARKET_SOURCE_A_URL` and `HB_MARKET_SOURCE_B_URL` in the process environment. The default adapters are `coingecko` and `coinbase`.

`python accelerator.py market-collect --policy policy.json --out market-observation.json`

Expected public JSON shapes:
- CoinGecko: `{"bitcoin":{"eur":...}}`
- Coinbase: `{"data":{"amount":"...","currency":"EUR"}}`

## Evaluate
`python accelerator.py status --db history.sqlite --policy policy.json --market market-observation.json`

`python accelerator.py recommend --db history.sqlite --policy policy.json --market market-observation.json --out proposal.json`

A non-HOLD recommendation is still only a signed-proposal candidate for Node Stage B. It is not permission to apply.
